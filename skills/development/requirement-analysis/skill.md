# 需求分析技能

## 目的
将用户请求转化为清晰、可执行的需求，并定义验收标准。

## 流程

### 1. 需求获取
- 倾听用户需求
- 提出澄清问题
- 识别隐含需求
- 理解上下文和约束

### 2. 需求分析
- 分类需求（功能性/非功能性）
- 识别依赖关系
- 评估可行性
- 排列优先级

### 3. 需求规格化
- 编写清晰的需求陈述
- 定义验收标准
- 记录假设条件
- 标注约束条件

### 4. 需求验证
- 与相关方确认
- 确保完整性
- 验证可测试性
- 确认理解一致

## 输入
- 用户请求或特性描述
- 项目上下文
- 现有系统约束

## 输出
```markdown
## 需求文档

### 功能性需求
- **FR-1**: [清晰、可测试的需求]
- **FR-2**: [清晰、可测试的需求]

### 非功能性需求
- **NFR-1**: 性能 - [具体指标]
- **NFR-2**: 安全 - [具体要求]

### 验收标准
- [ ] AC-1: [具体、可测试的标准]
- [ ] AC-2: [具体、可测试的标准]

### 假设条件
- [假设 1]

### 约束条件
- [约束 1]

### 不包含范围
- [不在此次范围内的内容]
```

## 示例

**输入**: "添加用户认证"

**输出**:
```markdown
### 功能性需求
- **FR-1**: 用户可以通过邮箱和密码注册
- **FR-2**: 用户可以使用凭证登录
- **FR-3**: 系统支持通过邮箱重置密码
- **FR-4**: 用户可以退出登录

### 非功能性需求
- **NFR-1**: 密码必须使用 bcrypt 哈希
- **NFR-2**: 会话在 30 分钟不活跃后超时
- **NFR-3**: 登录页面必须在 2 秒内加载

### 验收标准
- [ ] 用户可以用有效邮箱和强密码注册
- [ ] 用户不能用重复邮箱注册
- [ ] 用户可以用正确凭证登录
- [ ] 错误凭证时显示错误信息
- [ ] 用户在 5 分钟内收到密码重置邮件
- [ ] 用户会话在 30 分钟后过期

### 假设条件
- 邮件服务可用
- 用户可以访问邮箱

### 约束条件
- 必须符合数据保护法规
- 必须支持移动端和桌面端

### 不包含范围
- 社交登录 (OAuth)
- 双因素认证
```
