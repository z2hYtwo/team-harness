# 架构设计技能

## 目的
为特性和系统设计可扩展、可维护的技术架构。

## 流程

### 1. 需求审查
- 理解功能性需求
- 识别非功能性需求
- 记录约束和假设

### 2. 高层设计
- 定义系统组件
- 设计组件交互
- 选择技术栈
- 规划数据流

### 3. 详细设计
- 定义 API 和接口
- 设计数据模型
- 规划错误处理
- 考虑安全性

### 4. 设计验证
- 对照需求审查
- 评估可扩展性
- 评价可维护性
- 分析取舍

## 输入
- 需求规格
- 系统约束
- 技术偏好
- 现有架构

## 示例

**输入**: 用户认证需求

**输出**:
```markdown
### 高层架构
┌─────────────┐
│   客户端    │
└──────┬──────┘
       │
       ↓
┌─────────────┐
│  认证 API   │
└──────┬──────┘
       │
       ├──→ ┌──────────────┐
       │    │  用户服务    │
       │    └──────────────┘
       │
       └──→ ┌──────────────┐
            │  邮件服务    │
            └──────────────┘

### 组件

**认证 API**
- 职责: 处理认证请求
- 接口: REST API (POST /auth/register, /auth/login, /auth/logout)
- 依赖: 用户服务, 邮件服务

**用户服务**
- 职责: 用户 CRUD, 密码管理
- 接口: 内部服务调用
- 依赖: 用户数据库

**邮件服务**
- 职责: 发送邮件（验证, 密码重置）
- 接口: 内部服务调用
- 依赖: 邮件服务商 API

### 数据模型
Table: users
- id (UUID, PK)
- email (VARCHAR, UNIQUE, NOT NULL)
- password_hash (VARCHAR, NOT NULL)
- created_at (TIMESTAMP)
- last_login (TIMESTAMP)

Table: sessions
- id (UUID, PK)
- user_id (UUID, FK -> users.id)
- token (VARCHAR, UNIQUE)
- expires_at (TIMESTAMP)
- created_at (TIMESTAMP)

### 技术栈
- **语言**: Java 17 (项目标准)
- **框架**: Spring Boot 3.2 (现有技术栈)
- **安全**: Spring Security + JWT (行业标准)
- **数据库**: PostgreSQL (现有基础设施)
- **密码哈希**: BCrypt (安全最佳实践)

### 设计决策

**决策**: 使用 JWT 管理会话
- 备选: 服务端 Session, JWT, OAuth2
- 选定: JWT
- 理由: 无状态, 可扩展, 对移动端友好

**决策**: 独立用户服务
- 备选: 单体 Controller, 独立服务
- 选定: 独立服务
- 理由: 更好的关注点分离, 可复用
```
