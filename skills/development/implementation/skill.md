# 编码实现技能

## 目的
将设计和任务规格转化为简洁、高效、可维护的生产级代码。

## 流程

### 1. 任务理解
- 审查任务需求
- 理解验收标准
- 检查架构设计
- 识别依赖关系

### 2. 编码
- 编写实现代码
- 遵循编码规范
- 应用设计模式
- 处理边界情况

### 3. 测试
- 编写单元测试
- 确保覆盖率
- 测试边界情况
- 验证功能

### 4. 文档
- 为复杂逻辑添加注释
- 记录公共 API
- 更新相关文档

## 编码规范

### 代码质量
- **清晰命名**: 使用描述性名称，避免缩写
- **单一职责**: 每个函数/类只做一件事
- **DRY**: 不重复自己
- **小函数**: 保持函数专注和简短
- **格式一致**: 遵循项目风格指南

### 错误处理
- 在系统边界处验证输入
- 提供有意义的错误信息
- 使用恰当的异常类型
- 带上下文记录日志

### 安全
- 清洗所有用户输入
- 使用参数化查询（防止 SQL 注入）
- 验证和转义数据
- 保护敏感信息

### 性能
- 选择合适的数据结构
- 避免过早优化
- 考虑算法复杂度
- 必要时做性能分析

## 输入
- 任务规格
- 架构设计
- 编码规范
- 现有代码上下文

## 输出
- 生产代码
- 单元测试
- 文档更新
- 实现说明

## 最佳实践

### Java/Spring Boot
- 使用构造函数注入
- 利用 Spring Boot 自动配置
- 用 `@Valid` 做请求校验
- 返回恰当的 HTTP 状态码
- 用 record 做不可变 DTO

### 测试
- 测试正常路径和异常路径
- 使用有意义的测试名称
- Mock 外部依赖
- 业务逻辑覆盖率 >80%
- 测试边界条件

### 文档
- 记录复杂算法
- 解释非显而易见的决策
- 保持注释与代码同步
- 不记录显而易见的代码
