# 调试技能

## 目的
通过结构化调查和根因分析，系统化地诊断和修复 Bug。

## 流程

### 1. 问题理解
- 仔细阅读 Bug 报告
- 澄清复现步骤
- 理解预期与实际行为的差异
- 收集环境信息

### 2. 复现
- 搭建测试环境
- 按步骤复现
- 确认 Bug 存在
- 记录观察结果

### 3. 调查
- 审查相关代码
- 分析堆栈信息
- 检查日志
- 使用调试工具

### 4. 根因分析
- 定位确切原因
- 理解触发条件
- 排查关联问题
- 评估影响范围

### 5. 修复实现
- 设计最小修复方案
- 实现解决方案
- 添加回归测试
- 验证修复有效

## 调试技术

### 代码分析
- **静态分析**: 阅读代码流程
- **Git blame**: 找到代码引入时间
- **Git log**: 检查相关变更
- **依赖分析**: 检查上下游

### 动态分析
- **日志**: 添加策略性日志语句
- **调试**: 使用断点和单步执行
- **性能分析**: 识别性能问题
- **追踪**: 跟踪执行路径

### 系统方法
- **二分法**: 缩小问题范围
- **假设验证**: 提出并验证理论
- **隔离法**: 逐一排除变量
- **对比法**: 比较正常和异常情况

## 输入
- Bug 报告及复现步骤
- 堆栈信息或错误日志
- 环境信息
- 预期行为

## 常见 Bug 模式

### 空指针异常
- 解引用前检查 null
- 使用 Optional 或 null 检查
- 验证输入

### 并发修改异常
- 迭代时不修改集合
- 使用线程安全集合
- 同步访问

### 内存泄漏
- 关闭资源 (try-with-resources)
- 移除监听器
- 清除引用

### 性能问题
- 检查 O(n²) 算法
- 审查数据库查询 (N+1)
- 分析热点路径
