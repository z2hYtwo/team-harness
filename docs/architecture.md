# Team Harness 架构文档

## 概述
Team Harness 是一个多 Agent AI 开发框架，通过结构化工作流协调专业 Agent，交付高质量的软件开发成果。

## 核心概念

### 1. 规则 (Rules)
全局和特定语言的编码标准，所有 Agent 必须遵循。

**结构**:
```
rules/
├── global/          # 通用规则
│   └── base.md
├── java/            # Java 规则
│   └── java-backend.md
└── frontend/        # 前端规则
```

**目的**: 确保所有代码生成的一致性、质量和最佳实践。

### 2. 技能 (Skills)
Agent 可调用的可复用能力单元。

**结构**:
```
skills/
├── common/                    # 通用技能
├── development/               # 开发生命周期技能
│   ├── requirement-analysis/
│   ├── architecture-design/
│   ├── task-planning/
│   ├── implementation/
│   ├── debugging/
│   ├── testing/
│   └── code-review/
└── technology/                # 技术栈技能
    ├── java/
    ├── springboot/
    ├── mysql/
    └── vue/
```

**分类**:
- **通用 (Common)**: 跨领域技能
- **开发 (Development)**: SDLC 阶段技能
- **技术 (Technology)**: 技术栈专项
- **业务 (Business)**: 领域专项知识

### 3. 工作流 (Workflows)
编排技能和 Agent 的完整开发流程。

**可用工作流**:
- `feature.md`: 完整特性开发生命周期
- `bugfix.md`: 系统化 Bug 调查和修复
- `refactor.md`: 代码质量改善流程
- `review.md`: 全面代码审查
- `testing.md`: 多层级测试策略
- `release.md`: 发布管理和部署

**目的**: 引导复杂的多步骤流程从头到尾完成。

### 4. Agent (智能体)
具有特定角色和专长的 AI Agent。

**Agent 类型**:
- **Planner (规划)**: 战略规划和任务分解
- **Coder (编码)**: 代码实现和编写
- **Reviewer (审查)**: 质量保障和代码审查
- **Debugger (调试)**: 问题诊断和修复

**属性**:
- 名称和描述
- 模型配置
- 职责范围
- 输出格式
- 交互风格

### 5. 模板 (Templates)
标准化的文档格式，确保输出一致性。

**可用模板**:
- `AGENTS.md`: 项目 AI 指南模板
- `project.md`: 项目描述模板
- `task.md`: 任务规格模板
- `plan.md`: 实施计划模板

## 系统架构

### Agent 协作流程

```
用户请求
    ↓
工作流选择
    ↓
Agent 协调
    ↓
    ├─→ 规划 Agent ──→ 创建计划
    ├─→ 编码 Agent ──→ 实现代码
    ├─→ 审查 Agent ──→ 审查代码
    └─→ 调试 Agent ──→ 修复问题
    ↓
交付产出
```

### 组件交互

```
┌─────────────┐
│    规则     │◄─────┐
└─────────────┘      │
                     │ 被查阅
┌─────────────┐      │
│    技能     │◄─────┤
└─────────────┘      │
       ▲             │
       │ 被调用      │
       │             │
┌─────────────┐      │
│   工作流    │──────┤
└─────────────┘      │
       ▲             │
       │ 被执行      │
       │             │
┌─────────────┐      │
│   Agent     │──────┘
└─────────────┘
       ▲
       │ 被实例化
       │
┌─────────────┐
│    模板     │
└─────────────┘
```

## 设计原则

### 1. 模块化
每个组件（规则、技能、工作流、Agent）独立且可复用。

### 2. 可组合性
组件可以不同方式组合以实现各种目标。

### 3. 专业化
每个 Agent 有特定角色和专长领域。

### 4. 一致性
模板和规则确保统一的输出质量。

### 5. 可扩展性
可添加新技能、工作流和 Agent 而不修改现有组件。

## 使用模式

### 模式 1: 特性开发
```
用户: "实现用户认证"
  → feature.md 工作流
    → 规划 Agent (需求分析, 任务规划)
    → 编码 Agent (代码实现)
    → 审查 Agent (代码审查)
    → 交付: 可工作的特性 + 测试
```

### 模式 2: Bug 修复
```
用户: "修复登录超时问题"
  → bugfix.md 工作流
    → 调试 Agent (根因分析)
    → 编码 Agent (修复实现)
    → 审查 Agent (修复验证)
    → 交付: Bug 修复 + 回归测试
```

### 模式 3: 代码审查
```
用户: "审查 PR #123"
  → review.md 工作流
    → 审查 Agent (全面审查)
    → 交付: 审查意见和批准
```

## 扩展方式

### 添加新技能
1. 在合适的分类下创建技能目录
2. 定义技能元数据和实现
3. 记录输入、输出和用法
4. 将技能加入相关工作流

### 添加新 Agent
1. 在 `agents/` 下创建 Agent 定义
2. 指定模型、职责和行为
3. 定义输出格式和交互风格
4. 更新工作流以使用新 Agent

### 添加新工作流
1. 在 `workflows/` 下创建工作流文件
2. 定义阶段和技能调用
3. 指定进入和退出条件
4. 记录用法和示例

### 添加新规则
1. 在合适的分类下创建规则文件
2. 定义标准和指南
3. 确保规则适用于对应语言/技术
4. 在相关技能和 Agent 中引用

## 质量门禁

每个工作流包含内置质量门禁：
- **需求**: 清晰的验收标准
- **实现**: 代码规范合规
- **测试**: 覆盖率和质量阈值
- **审查**: 同行验证
- **部署**: 生产就绪检查

## 最佳实践

### 对使用者
- 为任务选择合适的工作流
- 提供清晰的需求和上下文
- 审查 Agent 输出并提供反馈
- 使用模板确保一致性

### 对 Agent
- 严格遵循规则
- 按设计使用技能
- 按模板产出结构化输出
- 记录决策和取舍
- 需要时提出澄清问题

### 对系统维护
- 与最佳实践同步更新规则
- 基于使用模式演进技能
- 基于执行结果优化工作流
- 基于反馈更新 Agent 行为
- 保持模板的时效性
